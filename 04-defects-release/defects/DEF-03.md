## ขั้นตอนทำซ้ำ

1. ส่ง `POST /api/v1/auth/register` ด้วยรหัสผ่าน 7 ตัวอักษร (`Test123`)
2. ทำซ้ำด้วยรหัสผ่านว่าง

## ผลที่คาดหวัง (อ้างกฎ)

HTTP 400 พร้อมข้อความ `Password must be at least 8 characters` และไม่สร้างผู้ใช้ (REQ-01 FR-AUTH-01 AC-4)

## ผลจริง

HTTP 422 พร้อมโครงสร้าง validation ของ Pydantic (`string_too_short`, `ctx.min_length = 8`) แม้จะไม่สร้างผู้ใช้จริง

## หลักฐาน

`../../03-test-execution/evidence/s3-api-reference-run.txt` บรรทัด TC-01 และ TC-03

## ผลกระทบ

client ที่ยึดสัญญา 400 ตาม SRS จะแสดงข้อผิดพลาดผิดรูปแบบ และข้อความที่ผู้ใช้เห็นไม่ตรงกับที่กำหนด body 422 ยังสะท้อนค่ารหัสผ่านที่ผู้ใช้กรอกในฟิลด์ `input` ซึ่งอาจรั่วไปยัง log/เครื่องมือติดตามข้อผิดพลาด เอกสารทดสอบของโปรเจกต์เอง (`tests_all/manual_tests/test_cases_backend.md` TC-BE-AUTH-07) กลับระบุ 422 เป็นผลที่คาด จึงเป็นความขัดแย้งระหว่าง SRS AC-4 กับ test doc ที่ต้องตัดสินก่อนแก้

## สาเหตุที่น่าจะเป็น

ใช้ `Field(min_length=8)` ใน `RegisterRequest` ทำให้ FastAPI คืน 422 ก่อนเข้าสู่ route และไม่มี exception handler แปลงเป็น 400

## แนวทางแก้

เพิ่ม validator/exception handler ที่แปลงกรณีความยาวรหัสผ่านเป็น HTTP 400 พร้อมข้อความตาม AC-4 หรือปรับสัญญา API อย่างเป็นทางการหากทีมเลือกใช้ 422 ปิดการ echo ค่าฟิลด์รหัสผ่านใน error response
