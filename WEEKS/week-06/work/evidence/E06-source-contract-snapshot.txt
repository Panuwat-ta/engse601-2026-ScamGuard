Observed contract facts:
- POST /scan/ has no explicit 202 status_code and FastAPI therefore returns the normal success status for the handler.
- Mobile cancelScan issues DELETE /scan/{id}, while the scan router source snapshot contains POST/GET only.
- Redis miss path writes json.dumps(inference_result) after removing heatmap_bytes only when the value is truthy; empty bytes remain and can break JSON serialization.
- Stored heatmap_image_url is the filesystem heatmap_path, while /uploads is separately mounted by the API.
- Source dimension uses settings.DEFAULT_SOURCE_SCORE in the baseline.
- History accepts page/limit/keyword/risk_level and returns HistoryListResponse items; start_date/end_date/risk_grade are absent from this route signature.
- Report creation uses HTTP 201 and returns key id; duplicate report error detail is "This scan has already been reported".
