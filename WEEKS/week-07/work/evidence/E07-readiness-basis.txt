Confirmed readiness facts on the frozen baseline:
1. Scan router exposes POST /scan/ and GET /scan/{id}; POST has no explicit 202 status code.
2. Mobile consumer had a DELETE /scan/{id} cancel call while scan router lacked that route.
3. Scan response contains id/status/progress fields suitable for polling.
4. Cache/heatmap lifecycle had unusable-reference and serialization risks.
5. Visual output lacked separate forgery_confidence and ai_gen_confidence fields.
6. Production source-verification adapter was not available; default source scoring was used.
7. Heatmap reference stored a filesystem path while media was served through /uploads.
8. History/report contracts had filter/field differences that must be rechecked end to end.
9. Consent enforcement and consent-management/log-access routes were not acceptance-ready.

Use in Week 07:
- These facts prioritize and gate scenarios; they are not counted as Week 07 end-to-end execution.
- Any new build must be re-baselined and re-tested before a Pass/Fail claim.
- Local ENGSE212 develop working-tree content is not used as the main acceptance baseline.
